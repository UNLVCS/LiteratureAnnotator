# Vault runbook

Vault holds the credentials for this stack. See
[docs/secret-flows.md](docs/secret-flows.md) for how secrets actually reach
each service.

Vault runs as the `vault` service in `label_api/docker-compose.yml`, listens on
`:8200` over TLS, and stores data in the `vault_data` volume (raft, single node).

## Everyday operations

### After any Vault restart or host reboot — unseal

Vault comes up **sealed** and serves nothing until unsealed. This is manual by
design; the unseal key is not stored anywhere on this machine.

```bash
docker exec -e VAULT_ADDR=https://127.0.0.1:8200 \
  -e VAULT_CACERT=/vault/tls/vault-cert.pem \
  annotation-vault vault operator unseal <unseal-key>
```

Symptoms of a sealed Vault: the `annotation-vault` healthcheck fails, and
`fastapi-backend` logs `[Vault] UNAVAILABLE - falling back to YAML config`.

### Starting the stack

Compose substitutes `${REDIS_PASSWORD}` and friends *before* any container
runs, so it cannot ask Vault itself. Render the env file first:

```bash
./ops/vault/render_compose_env.sh
cd label_api && docker compose up -d
```

### Checking where secrets came from

`fastapi-backend` prints one of these at startup:

- `[Vault] loaded secrets for: ...` — came from Vault
- `[Vault] UNAVAILABLE - falling back to YAML config: ...` — Vault was
  unreachable and the values in `.env.yaml` were used instead

## Rotation

| Script | What it rotates | Cadence |
|---|---|---|
| `ops/vault/rotate_redis.sh` | Redis password | monthly |
| `ops/vault/rotate_minio.sh` | MinIO root credentials | monthly |
| `ops/vault/refresh_postgres_creds.sh` | Label Studio's Postgres credentials | hourly |
| `ops/vault/rotate_saas_key.sh <provider>` | Pinecone / Label Studio / OpenAI / NCBI keys | manual |

The SaaS keys are semi-manual: none of those providers offer a self-service
rotation API, so you generate the replacement in their dashboard, run the
script to store it, then revoke the old key on their side.

### Suggested crontab

Run as the account that owns this checkout:

```cron
0 3 1 * *  cd /home/abreham/LiteratureAnnotator && ./ops/vault/rotate_redis.sh          >> ops/vault/rotate.log 2>&1
0 4 1 * *  cd /home/abreham/LiteratureAnnotator && ./ops/vault/rotate_minio.sh          >> ops/vault/rotate.log 2>&1
0 * * * *  cd /home/abreham/LiteratureAnnotator && ./ops/vault/refresh_postgres_creds.sh >> ops/vault/rotate.log 2>&1
```

**Before scheduling `rotate_redis.sh`**, migrate the other cross-network app
that connects to Redis directly — it loses access on the first rotation
otherwise. Same applies to `rotate_minio.sh` and anything reading those
buckets (host scripts, SLURM jobs).

## Postgres dynamic credentials

Postgres is the one backend with true dynamic secrets. Vault holds the
superuser credential (`secret/literature-annotator/postgres-admin`) and mints
short-lived roles (24h TTL, 72h max) that inherit from `labelstudio_app`,
which owns all the application tables.

Label Studio is an unmodified image that cannot re-fetch mid-lease, so
`refresh_postgres_creds.sh` runs hourly and recreates the container. Vault
drops the previous role when its lease expires.

Rotating the superuser password itself is rare and manual:

```bash
docker exec -i annotation-postgres psql -U labelstudio -d labelstudio \
  -c "ALTER USER labelstudio WITH PASSWORD '<new>';"
# then update Vault, so it can still connect as admin:
#   vault kv put secret/literature-annotator/postgres-admin username=labelstudio password='<new>'
#   vault write database/config/postgres ... password='<new>'
```

## SLURM jobs

Compute nodes may have no route to Vault. Run this on the login node before
`sbatch`:

```bash
VAULT_ADDR=https://vostok.cs.unlv.edu:8200 VAULT_CACERT=/path/to/vault-cert.pem \
VAULT_ROLE_ID=... VAULT_SECRET_ID_FILE=~/.vault-secret-id \
  ./ops/vault/prepare_slurm_secrets.sh
```

It writes `override.env.yaml` (mode 600, gitignored), which
`load_app_config()` merges automatically. Delete it once the job finishes.

## TLS

The cert is self-signed and generated by `ops/vault/generate_tls.sh` (10-year
expiry). Any machine talking to Vault needs a copy of
`vault/tls/vault-cert.pem` and must point `VAULT_CACERT` at it.

## One-time setup (already done — for reference or rebuild)

```bash
./ops/vault/generate_tls.sh                                   # TLS cert
cd label_api && docker compose up -d vault && cd ..
docker exec ... vault operator init -key-shares=1 -key-threshold=1
docker exec ... vault operator unseal <key>
VAULT_TOKEN=<root> ./ops/vault/bootstrap.sh                   # KV, policies, AppRoles
./ops/vault/migrate_secrets.sh                                # copy YAML secrets in
VAULT_TOKEN=<root> ./ops/vault/bootstrap_postgres_engine.sh   # dynamic Postgres creds
```

The unseal key and root token are produced once by `operator init` and are not
recoverable. Keep them in a password manager, not on this host.
